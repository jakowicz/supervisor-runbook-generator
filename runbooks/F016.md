## Objective

Create `projects/<project-slug>/README.md` as the human handoff for this
project-scoped factory. Explain the three levels of work: the source brief and
canonical specification; B-series authoring runbooks; and R-series
implementation runbooks. Document ordinary Supervisor commands for each level
and the chosen agent pipeline for the eventual implementation project. Explain
that R files are generated by B writers but accepted only after Supervisor runs
their configured execution and completion-audit stages.

## Acceptance criteria

- The README gives exact, project-relative commands to run the factory, then
  the B-series collection, then selected/all R-series implementation contracts.
- It explains that ordinary `supervisor-run --project <name>` follows the
  registered B and then R child collections automatically; users do not need to
  launch each generated R file by hand.
- It distinguishes an R file being **generated** from it being **accepted**:
  acceptance follows the project `.env` pipeline, task acceptance criteria,
  required evidence, and completion audit. It names the R collection state path
  (`.state/runbooks.sqlite3`) and explains that a non-accepted task safely
  resumes at its saved stage on the next project run.
- It names all generated directories, source-of-truth files, manifests,
  validation reports, evidence locations, and safe resume points.
- It explains how a large project scales: run a dispatcher wave, run the newly
  allocated B-series tasks, validate, and repeat until the final audit. Keep
  B-series batches bounded and add new waves for approved scope changes rather
  than mutating accepted contracts.
- It states that responsive web/PWA is included by default but all platform
  requirements come from the selected targets in the original brief.
- It preserves non-goals, original-design/reference boundaries, human gates,
  and the fact that authoring contracts is not implementation or release.
- It links the domain-discovery map and canonical specification so a future
  reviewer can see why the generated runbooks include the systems they do.
