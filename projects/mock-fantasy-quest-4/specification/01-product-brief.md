# 01 — Product brief

**Canonical normalized brief:** [`../PROJECT_BRIEF.md`](../PROJECT_BRIEF.md).
`INITIAL.md` remains the source of truth. This specification intentionally adds
no requirements or decisions beyond that document.

## Release definition

Deliver an original, small, offline-capable 2D single-player fantasy RPG for a
responsive public web application and installable PWA. The complete path is one
town, one dungeon, onboarding, readable narrative/quests, tutorialized
party-based turn-based combat, inventory/progression, save/load/recovery,
settings/accessibility, and a short ending.

## Requirement handling

- Direct requests define the candidate first-release scope and measurable
  outcomes in the canonical brief.
- Safe assumptions are temporary guardrails, not service, legal, technology,
  content, or vendor commitments.
- Deferred roadmap work is not release acceptance work.
- Connected services and commerce remain unresolved because they conflict with
  the stated offline single-player product; downstream contracts need human
  approval before selecting their architecture or policy.

## Originality boundary

The named game is a functional scope reference only. No branding, copy, assets,
layouts, interaction choreography, or other protected expression may be copied.
All content, presentation, mechanics expression, and player interfaces must be
independently designed.
