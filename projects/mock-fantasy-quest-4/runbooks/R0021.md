## Objective

Define a framework-neutral shared session model for launch, title, new-or-resume,
play, pause, ending, focus loss, and confirmed checkpoint presentation. It
coordinates the existing campaign and persistence boundaries without owning a
persistence driver, platform layout, cache lifecycle, or browser event binding.

## Dependencies

R0004 supplies safe persistence/checkpoint rules, R0006 supplies recovery
behaviour, and R0017 supplies campaign progression and completion state. This
contract consumes their stable outcomes; it does not change their ownership.
GATE-0003 remains an implementation gate for storage behaviour and GATE-0004
remains an implementation gate for concrete campaign assumptions.

## Ownership

- `src/app/session/` and `tests/app/session/`.
- Session and checkpoint view state, session intents, and safe-boundary API.
- Translation of confirmed persistence/campaign outcomes into an honest player
  session state.

## Required behaviour

Model the lifecycle as `launching → title → new-or-resume → playing ↔ paused →
ending → title`. Expose title actions only when available: without a valid
save, Continue and Load are absent or disabled with an explanation while New
game remains available. Resume starts only from a validated safe boundary.

Pause blocks world and combat advancement. A focus-loss intent safely pauses,
or first reaches an existing safe state where immediate pause is unsafe, and
records a once-per-session explanation for the presentation layer. Repeated
focus-loss, pause, resume, launch, and ending intents are idempotent and may
not duplicate rewards, campaign transitions, or save work.

Represent checkpoint status separately from a request or in-progress save.
Present a checkpoint as confirmed only after R0004 reports successful atomic
confirmation. Interrupted, failed, corrupt, or quarantined saves preserve the
last valid confirmed checkpoint and surface retry, return-to-title, and
fallback/new-game routes supplied by R0006. The session state must never imply
that unconfirmed work, an arbitrary combat moment, or remote data can resume.

## Web and PWA differences

Web and installed-PWA adapters consume the same session intents and confirmed
checkpoint state. Browser visibility hooks, service-worker/cache refresh,
installation prompts, update activation, viewport layout, and storage-driver
selection are adapter work and remain outside this shared model. An update may
be presented only at an existing save-safe title or paused-menu boundary; this
contract does not implement that lifecycle.

## Non-goals

Do not implement browser lifecycle listeners, cache refresh, service workers,
new save schemas, storage drivers, network services, account/sync, UI layout,
content, assets, audio, or a product gate approval. Do not resolve GATE-0003
or GATE-0004.

## Asset assessment

`asset_impact` is `not_applicable`: session and checkpoint state requires no
product visual or source asset. Do not create or reserve maps, sprites, icons,
fonts, illustrations, or other assets; `asset_ids` remains blank.

## Audio assessment

`audio_impact` is `not_applicable`: this contract selects no cue or playback
behaviour. Keep audio IDs, brief, duration, loop policy, and style version
blank/default; do not create incidental audio.

## Verification

- Use deterministic state fixtures to prove launch/title/new-or-resume/play/
  pause/ending transitions and that focus loss cannot advance world or combat
  state.
- Prove only a persistence-confirmed checkpoint is presented as confirmed;
  interrupted, failed, corrupt, and quarantined candidates retain the last
  valid boundary and expose the supplied recovery routes.
- Run duplicate focus, pause, resume, and completion intents to prove they do
  not replay rewards, transitions, or persistence work. Compare metadata,
  provenance, requirements, dependencies, and ownership to IMP-0021 and the
  manifest while retaining GATE-0003 and GATE-0004.

## Evidence

Retain state-transition traces, checkpoint-confirmation and recovery fixtures,
idempotence results, the manifest/catalogue comparison, and both unresolved
gate records.

## Acceptance criteria

- Session states cover safe launch, title, new-or-resume, play, pause, ending,
  and focus-loss behaviour without taking over persistence drivers or layout.
- A checkpoint is presented as confirmed only after durable confirmation;
  unconfirmed or invalid saves retain safe recovery routes.
- GATE-0003 and GATE-0004 remain explicit implementation gates.
