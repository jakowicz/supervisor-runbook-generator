## Objective

After DEC-0001 selects the framework, package manager, and CI baseline, create
the smallest reproducible project skeleton for the shared game core, web
adapter, and PWA adapter. Document one bootstrap, format, lint, and
deterministic test command interface, and make a clean approved-runtime
checkout run a deterministic sample test. This task establishes boundaries and
tooling only; it does not implement game behaviour or resolve the decision.

## Dependencies

This is the first implementation contract and has no R-series dependencies.
GATE-0001 / DEC-0001 is retained as a human implementation precondition:
authoring this runbook does not select a stack, and implementation must stop
before selecting or installing framework, package-manager, or CI tooling.

## Ownership

- Root build and tooling configuration, including the pinned toolchain
  declaration and command mapping.
- `src/core/`, `src/content/`, `src/app/`, `src/platform/web/`, and
  `src/platform/pwa/` ownership directories, created without feature code.
- `tests/` and an isolated deterministic sample-test location.
- `docs/development.md`, which records the approved-runtime bootstrap,
  format, lint, and deterministic-test commands once DEC-0001 is decided.
- The build/test command interface: `bootstrap`, `format`, `lint`, and
  `test:deterministic` (or the selected tool's documented equivalent).

## Behaviour

Use the DEC-0001-approved runtime only. Pin its version and package-manager
lock/metadata as appropriate to that approved selection. Create the isolated
directory skeleton so later work has distinct shared-core, content, app,
web-adapter, PWA-adapter, and test ownership.

Configure the selected tooling so the documented command interface has a
single reproducible mapping for bootstrap, formatting, linting, and a
deterministic sample test. The sample test must use no wall clock, network,
player data, browser storage, renderer, or platform feature. Record the exact
commands and a clean-checkout result in `docs/development.md`.

The skeleton must preserve the canonical direction: target adapters are
separate from the shared deterministic core, and no directory implies that a
target may change campaign rules. Later R0002 owns enforcement of detailed
core/adapter dependency rules.

## Web and PWA differences

The responsive web and installable PWA targets receive separate adapter
directories only. Neither adapter gains a renderer, service worker, cache
lifecycle, browser API dependency, or target-specific campaign behaviour in
this task. PWA installation, caching, offline delivery, and update activation
remain later scoped work; the PWA directory is an ownership boundary, not an
implementation of those features.

## Non-goals

Do not resolve DEC-0001 or choose a framework, package manager, CI provider,
host, storage API, browser/device matrix, or performance budget. Do not add
gameplay, campaign state, content, UI screens, renderer code, input handling,
service worker, persistence, network client, accounts, diagnostics, hosting,
or release automation. Do not claim browser/PWA compatibility or release
readiness.

## Asset assessment

`asset_impact` is `not_applicable`. The baseline contains only source,
configuration, test, and developer-documentation boundaries. Do not create or
add incidental product visuals, UI assets, illustrations, icons, fonts,
textures, sprites, maps, audio-visual assets, or copied reference styling;
`asset_ids` remains blank.

## Audio assessment

`audio_impact` is `not_applicable`. Do not create, add, reserve, or reference
music, sound effects, voice, or other product audio; the blank audio metadata
and zero duration intentionally record that exclusion.

## Verification

- Before implementation, confirm DEC-0001 is accepted and record the approved
  runtime, package manager, CI baseline, and pinned versions. If it remains
  unresolved, stop implementation and report GATE-0001 without substituting a
  tool choice.
- In a clean checkout of the approved runtime, run the exact documented
  bootstrap command, format check, lint check, and deterministic sample-test
  command.
- Verify the documented ownership directories exist and that the sample test
  is isolated from browser, network, storage, clock, and product data.
- Preserve command output, pinned-toolchain evidence, directory listing, and
  the deterministic test result in the implementation evidence.

## Evidence

`docs/development.md` must identify the selected command mapping and pinned
toolchain only after DEC-0001. The implementation record must retain the clean
checkout command outputs and show the isolated ownership directories. If the
gate is still blocked, retain this runbook and record that no implementation
tooling or product work was created.

## Acceptance criteria

- An approved-runtime clean checkout can run the documented bootstrap, format,
  lint, and deterministic sample-test commands successfully.
- Shared core, content, app, web-adapter, PWA-adapter, and test ownership
  directories are isolated without feature, renderer, storage, or service
  implementation.
- GATE-0001 / DEC-0001 remains explicit; this task neither selects the stack
  nor claims implementation, browser, PWA, or release readiness before that
  decision.
- No product visual or audio asset is created or introduced.
