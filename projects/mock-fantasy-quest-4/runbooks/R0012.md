## Objective

Create the bounded developer-documentation closure for the SHARD-01 foundation.
It cross-references the approved planning contracts for architecture ownership,
command flow, save-versus-cache recovery, and P0 connected-scope exclusion.
It is documentation work only: it neither implements these boundaries nor
claims their approval, product completion, or release readiness.

## Dependencies

R0002 defines the shared-core and adapter seam; R0004 owns deterministic
campaign-state transitions; R0006 owns the local save and recovery protocol;
and R0008 owns the P0 identity and connected-service exclusion. Their listed
contracts are prerequisites for this index, not evidence that implementation
or the B0004 checkpoint has been accepted. Retain GATE-0003 / DEC-0003 for
storage, quota, support, and recovery-policy choices, and GATE-0006 / DEC-0006
for any connected scope. No documented gate is resolved here.

## Required behaviour

Document the foundation architecture as a shared deterministic rules core,
content validator, browser presentation/input adapters, local save/recovery
repository, PWA release manager, and error/diagnostic boundary. State the
direction of interaction: adapters issue commands, only the rules core produces
durable campaign state, and the shell renders returned state/events without
mutating campaign state. Browser APIs, timers, network calls, and renderer
dependencies remain outside the core.

Document that the save repository owns serialized snapshots and recovery
metadata, while the shell owns ephemeral UI state. Record the write-ahead
replacement boundary: validate a complete candidate and read-back before
promoting a current pointer, retain a known-good snapshot, and quarantine
invalid or incompatible candidates. Preferences and PWA cache records are not
saves and cannot promote, overwrite, delete, synchronise, or imply success for
a campaign snapshot. Migration transformations remain a later pure-runner
concern; this index must not choose storage, quota, retention, support window,
or migration policy.

Document P0 as an offline local-profile boundary with no account, token, role,
remote profile, network client, cloud save, analytics transport, entitlement,
or connected campaign authority. Treat persisted bytes, content, browser
events, URL parameters, and service-worker messages as untrusted at their
respective boundaries. Any future connected proposal remains separately gated
and cannot redefine the local campaign as non-authoritative.

## Web and PWA differences

Responsive web and installed PWA share the same core, command, local-save,
preference, quarantine, and connected-scope boundaries. The PWA release/cache
manager may manage install and cached-release lifecycle but must remain separate
from campaign persistence: a cache refresh, update, or offline failure cannot
alter a confirmed save. This documentation does not select a browser-storage
mechanism, service-worker rollout policy, browser matrix, or PWA implementation.
