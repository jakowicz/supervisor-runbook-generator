## Objective

Define the semantic, responsive web/PWA game-shell contract around the shared
session and game state. It specifies labelled navigation, panel/focus routing,
viewport profiles, reflow, and non-colour cues without creating a PWA-specific
UI, final presentation assets, or fixed device-support claim.

## Dependencies

R0010 supplies the shared accessibility foundation and R0021 supplies session
and checkpoint presentation state. This shell consumes their public states and
routes panels to them without changing their APIs. GATE-0002 remains an
implementation gate for numeric/browser-device thresholds and GATE-0004
remains a gate for final content and layout choices.

## Ownership

- `src/app/shell/`, `src/platform/web/layout/`, and `tests/app/shell/`.
- Semantic navigation, viewport profiles, and panel/focus routing API.
- Title, main controls, status, temporary panels, dialogs, visible focus, and
  responsive reflow rules around shared game state.

## Required behaviour

Provide semantic landmarks for title navigation, main game controls, objective
or status, and dialogs. The game view is the primary workspace; Quest, Bag,
Party, Save, Settings, Help, privacy/diagnostics, and PWA status are labelled
temporary panels with a visible title, close control, and known return target.
Icons always have adjacent text or an accessible name. Title actions reflect
R0021 availability rather than promising unavailable save actions.

Panel changes preserve prior selection and scroll position where practical.
Closing returns focus to the invoking control; a newly opened non-modal panel
receives focus at its heading. Blocking dialogs describe consequences and use a
safe Cancel default. Browser Back closes a transient panel before any leave
prompt, and navigation may not silently discard recoverable progress.

Define narrow, medium, and wide profiles. Narrow layouts use safe-area-aware
world presentation, an expandable objective summary, reachable actions, and
full-screen panels with sticky close/back controls. Medium layouts retain a
primary world with contextual side or bottom panel; wide layouts use a centred
stage with a collapsible status rail and may use two-column inspection. Resize,
rotation, zoom, virtual keyboards, and PWA display-mode changes preserve game
state and selection where practical; if reflow obscures selection, focus moves
to the panel heading and announces the change.

Keep visible focus, labels, state text, and non-colour cues available across
profiles. Touch-operable controls retain the specified target/separation
contract; hover is optional enrichment. Text scaling, contrast, typography,
motion, and exact threshold verification remain governed by R0010 and the
unresolved GATE-0002 rather than being inferred here.

## Web and PWA differences

The responsive web shell and installed PWA consume the same semantic UI,
navigation, session state, and shared campaign rules. PWA display-mode reflow
uses the same profiles, not a forked UI. Installation, service workers, cache
refresh, update activation, and a final support matrix are outside this
contract and remain gated.

## Non-goals

Do not produce final art, fonts, UI assets, campaign content, audio, a fixed
browser/device matrix, service-worker behaviour, cache/update implementation,
or a duplicate PWA interface. Do not resolve GATE-0002 or GATE-0004.

## Asset assessment

`asset_impact` is `not_applicable`: semantic shell and layout rules create no
visual/source asset. Do not create or reserve icons, fonts, mockups,
illustrations, or other product assets; `asset_ids` remains blank.

## Audio assessment

`audio_impact` is `not_applicable`: this shell contract owns no cue selection,
playback, or mix. Keep all audio metadata blank/default and create no audio
asset.

## Verification

- Use representative session and viewport fixtures to prove labelled controls,
  legal focus order, panel return targets, and safe dialog defaults through
  resize and panel changes.
- Prove narrow, medium, and wide profiles retain all required controls without
  hover-only operation or a PWA-specific UI branch; test reflow focus recovery.
- Compare metadata, requirements, provenance, dependencies, and ownership to
  IMP-0022 and the manifest; retain GATE-0002 and GATE-0004 without treating
  documentation as approval.

## Evidence

Retain semantic-tree/focus traces, viewport and panel fixtures, PWA/web parity
comparison, metadata comparison, and the unresolved gate records.

## Acceptance criteria

- The shell supplies semantic navigation, labelled panels, safe dialog and
  focus routing, and responsive profiles around shared game state.
- Web and installed PWA share one UI contract; no PWA-specific interface,
  support-matrix claim, or lifecycle implementation is introduced.
- GATE-0002 and GATE-0004 remain explicit implementation gates.
