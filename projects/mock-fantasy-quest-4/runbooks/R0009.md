## Objective

Define a bounded, privacy-safe local diagnostic contract for future recovery
support: an explicitly consented, redacted local record, clear/delete controls,
and a recorder interface with no transport. It must help diagnose a recovery
condition without collecting save bytes, dialogue, identity, secrets, or a
remote analytics payload.

## Dependencies

R0002 provides the shared-core/adapter seam, R0003 provides deterministic
fixtures, and R0006 provides local save/recovery and quarantine boundaries.
Retain GATE-0005 / DEC-0005: a human decision is required before any transport,
retention, hosting, support, or data-handling claim. The gate blocks those
implementation choices, not authoring this local boundary.

## Ownership

- `src/platform/web/diagnostics/` local diagnostic adapter boundary.
- `src/app/recovery/diagnostic-contract.*` consent, record, redaction, and
  clear-control interface.
- `tests/platform/diagnostics.*` deterministic consent, redaction, and local
  deletion fixtures.
- `docs/privacy-and-recovery.md` diagnostic boundary documentation.
- Redacted local diagnostic record and consent-state data schemas.

The shared core does not own diagnostic storage or transport. R0006 owns save
data and recovery; this task may reference only stable non-content failure
categories needed for a local recovery record.

## Required behaviour

Default diagnostics to absent. The recorder creates a record only after an
explicit, revocable local consent state is present; a missing, declined, or
withdrawn consent state must create no record. Define a small allow-list such
as schema-safe failure category, local timestamp abstraction, app/build
identifier placeholder, and recovery action outcome only where the relevant
human decisions permit a value. Redact or reject all unrecognised fields.

Never capture save snapshots or bytes, checksums, slot names, preferences,
dialogue, authored content, free text, input sequences, account data, device
identifiers, IP/network data, cookies, tokens, credentials, stack payloads
that can expose content, or secrets. Provide a clear-local-record operation
that removes only diagnostics after explicit confirmation and visibly reports
the local result. The record must not influence save recovery or block play.

Enforce a no-network boundary: no provider, endpoint, request client, beacon,
upload queue, analytics SDK, background sync, remote retention, or export path
is permitted. A future transport proposal is separate work and remains halted
at GATE-0005 / DEC-0005.

## Web and PWA differences

Web and installed PWA share the same consent, redaction, clear, and no-network
contract. PWA installation, cache, or offline update state does not grant a
diagnostic upload or a separate retention policy. Any target-local storage
mechanism remains unselected until the retained gate is resolved.

## Non-goals

Do not integrate analytics, crash reporting, telemetry providers, transport,
hosting, remote support, retention schedules, export, identifiers, secrets,
accounts, sync, network services, UI screens, save-content inspection,
product assets, or audio. Do not claim legal, compliance, or support approval.

## Asset assessment

`asset_impact` is `not_applicable`. Local redacted records, consent state, and
deterministic fixtures require no product asset. Do not create or reserve
visual, source, audio, icon, illustration, font, texture, sprite, map, or
other incidental asset; `asset_ids` and audio IDs remain blank.

## Verification

- Run deterministic fixtures proving no record is created without consent and
  that withdrawal prevents subsequent recording.
- Test allow-list redaction against save bytes, dialogue/content, slot data,
  identifiers, credentials, tokens, request/endpoint fields, stack payloads,
  and unknown properties; all must be omitted or rejected.
- Test explicit local deletion removes only diagnostic records and leaves the
  save/recovery boundary unchanged.
- Run a static dependency scan proving no network, transport, provider,
  analytics, upload, or background-sync import/configuration exists.
- Before recording the B0005 checkpoint, load this runbook and compare its
  metadata, provenance, dependencies, requirement IDs, and ownership to the
  manifest. Stop on a mismatch; retain R0009 and never renumber or replace it.

## Evidence

Retain consent-state and absent-record fixture results, redaction/rejection
assertions, local-clear results, no-network scan output, the retained
GATE-0005 / DEC-0005 record, and the successful loader and manifest-comparison
record.

## Acceptance criteria

- Diagnostics are absent without consent, contain only allow-listed redacted
  local fields, and can be explicitly deleted without affecting save data.
- No diagnostic payload includes save or dialogue data, identity, secrets, or
  network/transport fields; no remote diagnostics path is introduced.
- Transport, retention, hosting, and support decisions remain blocked by
  GATE-0005 / DEC-0005 for both web and PWA paths.
