## Objective

Create the dependency policy and public contracts that keep the deterministic
shared core independent of browser, renderer, clock, network, and platform
modules. Adapters may submit commands and render returned state/events only.

## Dependencies

R0001 is an implementation dependency. Author and validate this contract now;
do not treat GATE-0001 as permission to implement or as a blocker to authoring.

## Ownership

- `src/core/public interfaces` and the `Command`, state, event, and adapter interfaces.
- `src/platform/{web,pwa}/adapter interfaces` and the dependency-policy manifest.
- `architecture dependency rules` and `docs/architecture.md`.

## Behaviour

Define an enforceable import direction in which the core accepts shared
commands, validates and returns state/events, while web and PWA adapters
translate platform input and render those returned values. The adapter must not
mutate campaign state directly. Keep the policy framework-neutral so a later
tool decision can choose its enforcement mechanism without changing the seam.

## Web and PWA differences

Both targets consume the same core contract. The web adapter owns browser
input, rendering, and viewport integration; the PWA adapter additionally owns
installation and cache-lifecycle adaptation. Neither target imports platform
concerns into the core or becomes a campaign authority.

## Non-goals

Do not implement combat, exploration, screens, campaign rules, accounts,
network clients, renderer behaviour, or target-specific rules. Do not create
assets, artwork, fonts, icons, audio, maps, or copied reference styling.

## Asset assessment

`asset_impact` is `not_applicable`. This interface and dependency-policy work
must not create incidental product assets; `asset_ids` remains blank.

## Verification

- Add a dependency-rule test that rejects forbidden core imports.
- Add a fixture adapter proving command-only interaction and returned
  state/event rendering.
- Record the selected enforcement mechanism only after the retained GATE-0001
  tool decision; do not claim that gate is resolved here.

## Evidence

Preserve the dependency-rule test result, the fixture-adapter result, and an
architecture document showing the one-way core/adapter boundary.

## Acceptance criteria

- Forbidden imports into the core are rejected.
- A fixture adapter can submit commands and consume returned state/events
  without directly mutating campaign state.
- The shared contract remains usable by web and PWA adapters without choosing
  implementation tooling or creating product assets.
