## Objective

Establish layered unit, content, integration, and reserved browser-test
conventions with isolated RNG, clock, and persistence fixtures. The harness
must be repeatable and must never access real services or player data.

## Dependencies

R0001 and R0002 are implementation dependencies. This contract may be authored
and structurally validated before they run; its later implementation uses the
shared seam from R0002.

## Ownership

- Test-runner configuration and `tests/{core,content,platform,app}/fixtures`.
- Deterministic fixture factories plus fake clock and RNG interfaces.
- `docs/testing.md` and the reserved browser-test convention.

## Behaviour

Provide factories that receive controlled clock, RNG, and storage fakes, reset
their state between cases, and expose explicit deterministic inputs. Define
separate layers for core, content, platform, and application checks so future
features add evidence at the appropriate layer instead of coupling tests to
real browser state or services.

## Web and PWA differences

Shared fixtures cover core behaviour. Web and PWA adapter tests use isolated
platform fakes; reserved browser tests are conventions only, not claims of a
real browser/device matrix. PWA cache and web origin storage remain distinct
from fixture storage.

## Non-goals

Do not add final feature assertions, real browser or device compatibility
claims, production telemetry, network calls, player data, campaign content, or
product assets. Do not create incidental art, fonts, icons, audio, maps, or
reference-derived fixture content.

## Asset assessment

`asset_impact` is `not_applicable`. Fixtures contain only deterministic,
non-product data and must not create incidental product assets or reserve them.

## Verification

- Run a representative core fixture repeatedly and prove identical results.
- Deliberately fail a fixture assertion and prove the runner reports it.
- Verify fixture storage is isolated from browser-origin and production data.
- Retain GATE-0002: this harness does not establish compatibility or
  performance claims.

## Evidence

Record repeated-run output, the deliberate-failure detection result, and an
isolation check showing no real service, player, or browser-origin storage use.

## Acceptance criteria

- Repeated execution of a controlled fixture returns identical results.
- Fixture state, clock, RNG, and storage are isolated and resettable.
- The harness defines layered conventions without asserting final features,
  browser/device support, or production telemetry.
