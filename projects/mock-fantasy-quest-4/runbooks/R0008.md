## Objective

Document and test the P0 negative boundary: local campaign start, save, and
resume require no account identifier, token, remote profile, authorization
role, entitlement, multiplayer, moderation, safety, or connected service.

## Dependencies

R0002 supplies the core/adapter dependency seam and R0004 supplies the local
campaign state envelope. They are implementation dependencies. Retain
GATE-0006 / DEC-0006: no connected feature may be implemented until its scope,
privacy, security, operational, cost, and failure-mode decisions are approved.

## Ownership

- `docs/security-boundary.md`.
- `tests/core/connected-scope-exclusion.*`.
- The future connected-service approval checklist and local-slot identity
  contract.

## Required behaviour

State that the local browser profile is the P0 player boundary, not an account
or authorization guarantee. The local campaign is the source of truth and has
no remote profile, analytics stream, purchase ledger, match state, cloud
backup, role, privilege, or entitlement. Local slot selection is an opaque
local reference only and must not contain identity, token, privilege, or remote
profile fields.

Add negative contract tests and a static boundary scan for P0 foundation
modules. They must fail on identity/token/role/entitlement fields, network or
server clients, sign-in/OAuth/sync paths, multiplayer/safety/moderation APIs,
purchase flows, or remote campaign authority. Treat future replication, if
ever approved, as a separate optional mirror rather than campaign truth.

## Web and PWA differences

Responsive web and installed PWA use the same local-slot contract and same
connected-scope exclusion. PWA installation, cache, and browser-origin storage
do not imply identity, authorization, sync, or a remote service. No target
obtains a distinct connected implementation path.

## Non-goals

Do not implement sign-in, OAuth, accounts, profiles, tokens, roles,
authorization, synchronization, server APIs, analytics transport, multiplayer,
moderation, reporting, purchases, entitlements, cloud saves, remote
diagnostics, or security claims about a device owner. Do not create product
assets, audio, or connected-service configuration.

## Asset assessment

`asset_impact` is `not_applicable`: this is documentation and negative test
coverage for an architectural exclusion. Do not create or reserve incidental
visual, source, audio, icon, illustration, font, texture, sprite, map, or
other product assets; `asset_ids` remains blank.

## Verification

- Run a static scan across P0 foundation modules for prohibited identity,
  token, privilege, entitlement, and network/server-client fields or imports.
- Run negative fixtures that attempt prohibited connected-scope configuration
  and prove the contract rejects or does not expose it.
- Verify start, local save, and local resume fixtures require only a local slot
  reference and no remote request or account data.
- Review `docs/security-boundary.md` against the exclusion list and record
  GATE-0006 / DEC-0006 as retained for any future connected proposal.

## Evidence

Retain static-scan and negative-fixture results, local start/save/resume test
output showing no remote request, the security-boundary review, and the future
connected-service approval checklist with its retained gate.

## Acceptance criteria

- P0 start, save, and resume expose no identity, token, role, entitlement,
  remote-profile, or network-client field or dependency.
- Negative tests prevent connected-service scope from entering P0 foundation
  modules for both web and PWA delivery paths.
- Any future connected work remains outside campaign truth and blocked by
  GATE-0006 / DEC-0006 rather than implicitly approved.
