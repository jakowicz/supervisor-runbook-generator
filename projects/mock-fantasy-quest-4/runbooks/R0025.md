## Objective

Define focus-safe, recoverable UI states for empty content, invalid actions,
save/recovery failures, destructive choices, and privacy-sensitive diagnostics.
The contract presents supplied session, persistence, and diagnostic outcomes
without introducing transport, cache lifecycle, automatic repair, or support
services.

## Dependencies

R0006 supplies local recovery semantics, R0009 supplies local-only diagnostic
boundaries, R0021 supplies session/checkpoint presentation, and R0022 supplies
dialogs and focus return. GATE-0003 retains storage/recovery policy and
GATE-0005 retains diagnostics transport and operations policy.

## Ownership

- `src/app/recovery/`, `src/app/dialogs/`, and `tests/app/recovery/`.
- Recovery and confirmation view state, plus recoverable-error and
  confirmation API contracts.
- Clear next-action copy, safe dialog defaults, and privacy presentation.

## Required behaviour

Empty inventory, quest, and save states state what is empty, why it may be,
and the next useful action. Invalid actions, locked exits, and unavailable
targets name the unmet requirement, preserve player/turn state, and return
focus to legal choices; generic error text alone is insufficient.

Save, corruption, and interrupted-write states never claim success before the
confirmed checkpoint supplied by R0021. Retain the last valid checkpoint and
offer only the recovery routes supplied by R0006: retry, return to title, and
fallback/new game. Quarantine messaging explains that data is preserved but
unusable and avoids blame. Fault recovery likewise offers plain-language retry,
title, and safe-recovery choices; a diagnostic option is optional and separate.

Delete-save confirmation names the selected slot and available progress/time,
states irreversibility, starts focus on Cancel, and makes Delete distinct. A
stale or repeated input cannot activate it. Deletion is limited to the selected
local slot and associated recovery metadata. New game explains replacement and
uses a separate slot or explicit replacement confirmation. Settings reset is
preference-only.

P0 sends no telemetry. Before local diagnostic creation/export, state purpose,
minimal fields, retention, deletion control, and no effect on play. Clear-data
confirmation is local-only; diagnostics UI never exposes save contents or
dialogue.

## Web and PWA differences

Web and installed PWA use the same recovery and dialog contract. PWA offline,
install, cache, and update messages only describe supplied status and save-safe
boundaries; no service-worker, cache, update, or remote-support lifecycle is
implemented or promised here.

## Non-goals

Do not select storage policy, send diagnostics, automate destructive repair,
create a cache lifecycle, expose remote support, alter persistence drivers,
make assets, or resolve GATE-0003 or GATE-0005.

## Asset assessment

`asset_impact` is `not_applicable`: recovery copy and view-state rules create
no product asset. `asset_ids` remains blank; do not create or reserve visual
or source assets.

## Audio assessment

`audio_impact` is `not_applicable`: recovery and confirmation state selects no
cue, playback, mix, or source audio. Keep all audio metadata blank/default.

## Verification

- Use fixtures to prove each empty/invalid state gives a legal next action and
  preserves state and focus.
- Prove failed/corrupt/interrupted saves retain the last valid checkpoint and
  offer only legal recovery routes without asserting unconfirmed success.
- Prove destructive dialogs start on Cancel and stale/repeated activation
  cannot delete; prove diagnostic copy stays local/minimised. Compare the
  contract with IMP-0025 and the manifest while retaining both gates.

## Evidence

Retain empty/invalid, checkpoint/recovery, destructive-confirmation,
diagnostic-boundary, focus-return, and manifest/catalogue fixtures, with the
unresolved GATE-0003 and GATE-0005 records.

## Acceptance criteria

- Empty, invalid, save-failure, and fault states preserve state and expose
  clear legal recovery actions.
- Destructive and diagnostics states are focus-safe, minimised, local-only,
  and cannot use stale/repeated activation to delete data.
- GATE-0003 and GATE-0005 remain explicit implementation gates.
