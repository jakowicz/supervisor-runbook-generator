## Objective

Specify the bounded, local save and recovery protocol for immutable revisions,
checksums, validated current pointers, known-good retention, quarantine,
separate preferences, explicit deletion, and save-safe boundaries. This is a
protocol and fixture contract, not approval to select a browser-storage API or
promise a quota, retention period, or migration-support window.

## Dependencies

R0002 provides the core/adapter seam, R0003 provides deterministic clock and
persistence fixtures, and R0004 supplies the immutable versioned campaign
snapshot and command/revision contracts. Retain GATE-0003 / DEC-0003: storage
API, quota, support window, and recovery policy require human approval before
implementation selects or relies on them. The gate blocks implementation
choices, not this contract's authoring.

## Ownership

- `src/core/save/{schema,compatibility,migrations}/` protocol contracts.
- `src/platform/web/persistence/` adapter boundary.
- `tests/{core,platform}/save*` fault and recovery fixtures.
- `docs/save-and-recovery.md`.
- Snapshot/preference/quarantine schemas and snapshot-repository/recovery API.

The shared layer owns snapshot shape, validation, compatibility, and recovery
semantics. The web adapter owns only the eventual approved local-storage
mechanism. PWA cache/install lifecycle, content registry, remote sync,
identity, diagnostics transport, and campaign transitions are not owned here.

## Required behaviour

Use a write-ahead replacement protocol: serialize a complete immutable
snapshot, validate checksum/schema/invariants, write a new revision candidate,
verify read-back, atomically mark a validated current pointer (or emulate it
with immutable records), and retain the prior known-good snapshot. Never clear
or overwrite the prior confirmed save until the new pointer is valid. Separate
preferences from campaign snapshots and never treat a cache record as a save.

Validate bounded, untrusted persisted bytes before parsing or use. A malformed,
checksum-invalid, incompatible, or migration-failed candidate is preserved with
its metadata in quarantine; it never replaces a valid save. Recovery offers
the last valid checkpoint or a clear new-game/fallback route. Loading restores
only safe scene boundaries. A failed quota, permission, or unavailable-storage
attempt leaves the session playable, says persistence did not succeed, and
offers non-blocking retry guidance.

Persist only at explicit safe boundaries: no unresolved combat turn or partial
command can become current. A stale writer must fail rather than replace the
latest revision. Deletion requires an explicit confirmation naming the selected
slot and its available progress/time; initial focus is Cancel, repeated/stale
input cannot activate Delete, and only that local slot and its recovery
metadata are removed.

Migration transformations remain ordered pure candidate transformations and
are not implemented or approved here beyond their compatibility boundary; R0007
owns the migration runner. No cloud, account, sync, cross-device merge, cache
eviction, or export/import promise is introduced.

## Web and PWA differences

Web and installed PWA share the same local snapshot, preference, validation,
quarantine, and recovery contract. The web adapter eventually binds an approved
same-origin storage mechanism; the PWA inherits it and must keep its
service-worker cache separate. A cache refresh or update failure neither
deletes, refreshes, nor synchronises save data, and no implementation may
claim persistence after an unconfirmed write.

## Non-goals

Do not choose a storage API, quota, eviction guarantee, support window,
retention policy, or migration set before GATE-0003 / DEC-0003 approval. Do not
implement cloud sync, accounts, remote deletion, cross-device conflict
resolution, PWA cache lifecycle, release update flow, diagnostics transport,
content validation, gameplay, UI screens, product assets, or audio.

## Verification

- Run deterministic fault fixtures for interrupted write, failed read-back,
  checksum failure, malformed/oversized bytes, unsupported version, storage
  quota/permission/unavailable failures, stale writer, quarantine, retry, and
  selected-slot deletion confirmation.
- Prove each failure preserves the last valid snapshot, does not report a save
  as successful, keeps the session usable where possible, and exposes the
  required retry/title/fallback/new-game recovery choice.
- Prove a current-pointer promotion occurs only after candidate validation and
  read-back; prove preferences and PWA cache fixtures cannot be read as or
  overwrite a campaign snapshot.
- Prove a pending command or unresolved combat turn cannot be committed and a
  stale/repeated delete action cannot remove an unselected slot.
- Before recording the B0004 checkpoint, validate the runbook loader parses
  this front matter, provenance is non-empty and maps to IMP-0006, dependencies
  match the manifest, owned paths do not overlap R0005's content boundary, and
  every required section is present. Stop on any mismatch; never overwrite an R contract.

## Evidence

Retain deterministic fault-fixture output, pre/post candidate and pointer
records, quarantine and recovery-path assertions, preference/save/cache
separation evidence, deletion-confirmation assertions, the retained
GATE-0003 / DEC-0003 record, and the pre-checkpoint loader, provenance,
dependency, ownership, and required-section validation record.

## Acceptance criteria

- Interrupted, invalid, incompatible, or failed save candidates cannot replace
  a validated current snapshot; the prior known-good snapshot is retained or
  malformed bytes are quarantined.
- Save snapshots, preferences, and PWA cache records remain separate, and
  local recovery presents clear retry, title, fallback, or new-game choices
  without claiming an unconfirmed save succeeded.
- Storage selection, quota, support window, migration policy, and recovery
  policy remain blocked by GATE-0003 / DEC-0003; no remote, cache, or asset
  work is introduced.
