## Objective

Define deterministic encounter, legal-action, defeat, and one-time reward
resolution contracts for the first battle. It establishes shared rules and
envelopes without party/enemy shapes, balance values, or presentation.

## Dependencies

R0003 supplies deterministic fixtures and R0004 supplies immutable command,
event, invariant, and RNG contracts. Neither ownership transfers here.
GATE-0004 remains an implementation gate for concrete party, enemy, and
balance shapes; it does not defer this contract's authoring.

## Ownership

- `src/core/campaign/{encounter,reward}*` and
  `tests/core/campaign/encounter*`.
- Encounter/action/defeat and reward envelopes, including stable reward IDs.
- Shared encounter commands and deterministic resolution/rejection rules.

## Required behaviour

Define encounter lifecycle states and legal actions as data-driven contracts
that use the core deterministic RNG state. Validate encounter status, expected
revision, action eligibility, targets, and interaction identity before any
resolution. Illegal, stale, or unavailable actions reject without mutation.
Defeat produces a safe typed outcome without silently granting success or
destroying required progress. A reward can be applied only by an eligible
resolved outcome and its stable reward ID grants once; retries return the
recorded result without duplicate reward application.

## Web and PWA differences

Web and PWA adapters send the same action commands and render returned events.
Animation timing, combat controls, haptics, sound, renderer choices, offline
shell lifecycle, and browser storage are outside the shared contract.

## Non-goals

Do not introduce multiplayer, live balance, concrete combatants, authored
stats, visual effects, combat art, audio, UI, mid-combat save guarantees,
network services, or presentation state. Do not resolve GATE-0004.

## Asset assessment

`asset_impact` is `not_applicable`: encounter and reward envelopes contain no
art/source asset. Do not create or reserve character, enemy, effect, icon,
sprite, texture, map, font, or other visual product asset; `asset_ids` remains
blank.

## Audio assessment

`audio_impact` is `not_applicable`: deterministic resolution does not own music
or sound-effect selection, triggers, or playback. Keep audio IDs and other
audio metadata blank/default and create no incidental cues.

## Verification

- Run deterministic fixture pairs with the same RNG state and assert identical
  legal action results, events, defeat outcomes, and reward application.
- Prove illegal actions, stale revisions, unavailable targets, and duplicate
  interaction/reward IDs preserve state or return the recorded prior outcome.
- Compare metadata, requirements, ownership, provenance, and dependencies with
  IMP-0015 and R0015's manifest allocation; retain GATE-0004 explicitly.

## Evidence

Retain deterministic encounter fixture output, invalid-action and duplicate-
reward results, the manifest/catalogue comparison, and the retained GATE-0004.

## Acceptance criteria

- Only legal encounter actions resolve; invalid actions do not mutate state.
- Defeat is safe and reward IDs apply exactly once under retry/replay.
- Concrete combatants, balance, art, audio, and UI remain out of scope, while
  GATE-0004 remains explicit for later implementation.
