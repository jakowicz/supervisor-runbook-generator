## Objective

Define the immutable, versioned shared campaign-state, command, result, event,
revision, interaction-ID, and deterministic-RNG contracts needed to validate
legal transitions. This foundation defines envelopes and invariants only; it
does not introduce a feature state machine or authored campaign values.

## Dependencies

R0002 provides the shared-core/adapter seam and R0003 provides deterministic
fixtures. They are implementation dependencies, not authoring blockers.
Retain GATE-0004: concrete party and content shapes remain unapproved.

## Ownership

- `src/core/{state,commands,events,invariants,rng}/`.
- The versioned campaign-snapshot envelope and deterministic RNG state.
- The public core command, state, event, result, revision, and interaction-ID
  interfaces, plus `tests/core/contract.*`.

## Required behaviour

Make state transitions pure and explicit: a command carries an expected
campaign revision and stable interaction/action ID; processing returns either
a typed rejection with no mutation or ordered state/events with a new revision.
Validate command shape, session state, identifiers, availability, eligibility,
predicates, and expected revision before any transition. Invariant helpers
must reject invalid state and preserve the prior immutable state.

Record deterministic RNG seed/state at safe boundaries. Require idempotency for
retries: a duplicate interaction ID or acknowledged durable transition returns
its prior result without a second reward, checkpoint, or revision-changing
transition. Process one command at a time per active campaign and reject stale
writers so visibility changes, repeated input, and concurrent tabs cannot
interleave a transition.

## Web and PWA differences

Web and PWA adapters submit the same shared command envelopes and consume the
same state/event results. Platform adapters may debounce controls and manage a
local slot lease/read-only warning, but neither gains authority to mutate state
directly. Installation, cache lifecycle, and storage-driver work are outside
this contract.

## Non-goals

Do not author content values; implement combat, inventory, quest, exploration,
or UI state machines; select party shapes; implement a save driver or cache;
add account, identity, token, role, network, or remote state; or create assets,
audio, maps, dialogue, or reference-derived content.

## Asset assessment

`asset_impact` is `not_applicable`: these serializable state and interface
contracts deliberately exclude authored content. Do not create or reserve
incidental visual, source, audio, font, icon, illustration, texture, sprite,
map, or other product assets; `asset_ids` remains blank.

## Verification

- Use R0003 deterministic fixtures to prove invalid commands leave the exact
  prior state unchanged and stale revisions reject without mutation.
- Prove a duplicate interaction ID returns the recorded prior outcome and
  produces no additional durable transition.
- Exercise controlled RNG state twice and compare state/event results.
- Exercise sequential command handling and a stale-writer fixture without
  selecting a browser-storage implementation.
- Record GATE-0004 as retained before adding concrete party/content shapes.

## Evidence

Retain contract-test output for invalid, stale, duplicate, deterministic-RNG,
and serialized transition cases, plus the public envelope/invariant inventory
and the retained GATE-0004 record.

## Acceptance criteria

- Invalid or stale commands cannot mutate campaign state.
- Duplicate interaction IDs are idempotent and cause no extra durable
  transition.
- State, command, result, event, revision, and RNG contracts are shared-core
  only, versioned where serialized, and independent of concrete content,
  persistence drivers, or connected scope.
