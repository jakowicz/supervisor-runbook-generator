## Objective

Define one semantic input-action vocabulary for web and PWA adapters, covering
movement, inspect/interact, confirm, cancel/pause, panels, navigation, and
legal combat action/target selection. It makes equivalent actions available
across keyboard, pointer, touch, and detected gamepad without creating
input-specific rules or committing to unsupported devices.

## Dependencies

R0002 supplies shared command/revision safety, R0021 supplies safe session and
pause intents, and R0022 supplies semantic controls and focus routing. This
contract maps physical input to those existing actions and does not alter game
rules, persistence, or shell ownership. GATE-0002 remains an implementation
gate for approved browser/device compatibility claims.

## Ownership

- `src/platform/web/input/`, `src/app/input/`, and `tests/platform/input/`.
- Input binding and availability state plus the semantic input-action API.
- Repeat, conflict, disconnect, and fallback handling for supported adapters.

## Required behaviour

Use a single action vocabulary: move, inspect/interact, confirm, cancel/pause,
open quest, open bag, open settings, navigate previous/next, and choose a
legal combat action/target. Equivalent actions invoke the same command and
receive the same state/result feedback. A core journey must not require pointer
precision, drag, multi-touch, rapid repetition, or a timeout.

Keyboard supports Arrow keys/WASD where appropriate, Tab/Shift+Tab in visual
reading order, Enter/Space confirm, Escape cancel/close/pause, and an early
Skip to game controls route. Pointer clicks operate the semantic controls;
right-click and hover are optional. Touch controls are labelled and reachable,
use explicit tap/target confirmation, and do not require pinch, swipe-only
navigation, double tap, drag, or long press.

Feature-detect gamepad input rather than promising a model. When detected,
pair action text with any glyph; map directional navigation, primary confirm,
secondary cancel, and menu pause. A disconnect preserves state and supplies
keyboard/mouse/touch alternatives without blocking. Focus-only browser input
uses the semantic focus order when presented, but continuous exploration on
unapproved targets is not promised. Standard semantic roles, names, states,
and labelled alternatives expose the same actions to browser assistive input;
voice recognition is neither required nor enabled.

Repeat handling must be action-aware. Navigation/movement repeat is bounded by
the shared command contract; confirm, destructive choices, legal combat
actions, and target selection accept one deliberate activation per eligible
state/revision. Stale, held, or repeated input may not confirm deletion,
consume multiple turns, replay rewards, or bypass a modal Cancel default.
Surface remap conflicts before saving, while leaving the approved depth of
remapping unresolved.

## Web and PWA differences

The same action vocabulary and adapters apply in responsive web and installed
PWA use. Availability may be reported from feature detection, but neither
surface promises a controller model or a final browser/device matrix. Native
clients, install lifecycle, cache behaviour, and PWA-specific rules are outside
this contract.

## Non-goals

Do not implement native clients, voice recognition, arbitrary remapping,
input-specific gameplay rules, final support guarantees, UI assets, audio,
storage drivers, or product gate approval. Do not resolve GATE-0002.

## Asset assessment

`asset_impact` is `not_applicable`: input semantics needs no product visual or
source asset. Do not create or reserve controller glyphs, icons, illustrations,
or other assets; `asset_ids` remains blank.

## Audio assessment

`audio_impact` is `not_applicable`: this contract selects no cue, playback, or
mix. Keep audio IDs, brief, duration, loop policy, and style version
blank/default and create no incidental audio.

## Verification

- Use deterministic adapter fixtures to prove keyboard, pointer, touch, and
  detected-gamepad events produce equivalent semantic actions and feedback.
- Prove held/repeated/stale input cannot duplicate destructive confirmation,
  combat selection, rewards, or commands; verify explicit legal-action and
  revision checks remain in place.
- Prove a gamepad disconnect preserves state and exposes a usable
  keyboard/mouse/touch fallback. Compare metadata, provenance, requirements,
  dependencies, and ownership to IMP-0023 and the manifest while retaining
  GATE-0002.

## Evidence

Retain cross-input action traces, repeat-safety and stale-input fixtures,
disconnect/fallback output, manifest/catalogue comparison, and the unresolved
GATE-0002 record.

## Acceptance criteria

- Keyboard, pointer, touch, and feature-detected gamepad map to equivalent
  semantic actions with labelled accessible fallbacks.
- Repeat, stale input, and gamepad disconnect cannot duplicate destructive or
  turn actions and leave a usable fallback.
- GATE-0002, remapping depth, and unapproved target compatibility remain
  explicit and unresolved.
